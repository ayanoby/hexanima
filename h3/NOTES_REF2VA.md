# MiniMax-H3 Ref2VA on the phone NPU (started 2026-11-16)

Source: Comfy-Org/MiniMax-H3 `diffusion_models/minimax_h3_ref2va_int8_convrot.safetensors` (34,038,894,550 B, int8 ConvRot, per-row F32 scale, groupsize 256 = the same format as the H3-Image file). Local copy: backups/h3-ref2va/ on the external disk.
Other files of the model family (not downloaded yet): video VAE `minimax_h3_video_vae_int8_convrot.safetensors`, audio VAE `minimax_h3_audio_vae_fp32.safetensors`, text encoder `qwen3vl_32b_minimax_h3_*` (the same Qwen3-VL-32B conditioner as H3-Image; our TE pack on the phone is reusable).
Ref2VA = reference-to-video with synchronized audio: text + up to 9 images / 3 videos / 3 audio clips (12 total) -> 24 fps RGB video and 32 kHz stereo audio, up to 362 frames per shot. License: MiniMax H3 Community License Agreement (territorial restrictions, see the H3 pack NOTICE).

## DiT (config in the safetensors metadata)
hidden 5376, 50 blocks, 56 heads x 128, ffn 14336 (SwiGLU 5376 -> 28672 -> 14336 -> 5376), token_refiner 2 layers, latents_dim 24 (video), audio_latents_dim 32, patch [1,2,2], text_dim 5120, time_embed_dim 2688, adaln_out 96768 (= 3 kinds x 6 x 5376), final_adaln_out 10752, rope_inv_freq_len 16.
Tensors: blocks.N.{adaln_proj.linear (int8 [96768,2688] + scale + bf16 bias), attn.qkv_proj (int8 [21504,5376], rows = [q;k;v], 7168 each), attn.out_proj [5376,7168], attn.q_norm/k_norm [128], mlp.fc1 [28672,5376] = [gate | up] (the image model has [up | gate]), mlp.fc2 [5376,14336], norm1/norm2 [5376]};
glue: video_patch_proj [5376,96] F32, audio_patch_proj [5376,32] F32, condition_proj [5376,5120] bf16, time_embedder.proj_in [5376,256] / proj_out [2688,5376] F32, final_layer.{adaln_proj [10752,2688] bf16, norm, video_out [96,5376], audio_out [32,5376]}, token_refiner.blocks.0..1 (bf16), rope.inv_freq [16].
Verified by weight correlation with the H3-Image blocks (cosine 0.95 on q/k/v rows, 0.91 on out, 0.90 on gate/up): the same base model, so the existing MODE 50 block kernel (hexagon/mega, h3) needs no change; only the pack front-end differs.

## Reference code read (vllm-omni, cloned to backups/h3-ref2va/refcode/vllm-omni, Apache-2.0; files vllm_omni/diffusion/models/minimax_h3/*.py, 21k lines in total)
- Time embedder: sinusoidal 256 (cos | sin, freqs exp(-ln(10000)*i/128)) -> proj_in (256->5376) -> SiLU -> proj_out (5376->2688), fp32.
- adaln per block: silu(t_emb [M,2688]) -> Linear 2688 -> 96768 (bf16 in the reference; the int8 file has ConvRot **groupsize 64** for adaln_proj, 256 for the rest: 2688 = 42 x 64; H64 is probably kron(h4,h4,h4)/8, to verify) -> view(M*3, 6*5376) -> chunk(6) = shift_msa, scale_msa, gate_msa, shift_mlp, scale_mlp, gate_mlp. M = number of UNIQUE condition embeddings (different timesteps / token groups), 3 = modality tags.
- Per token: combined_indices = inverse_index(unique t) * 3 + modality tag; norm1 -> scale/shift -> attention -> gated residual -> norm2 -> scale/shift -> MLP -> gated residual (same as the H3-Image block, but with M x 3 vector sets instead of 2 kinds).
- Rope: 3D (t,h,w), 16 freqs per axis (inv_freq = base^-(arange(0,32,2)/32), rope.inv_freq in the file), concatenated twice -> 96 of 128 dims rotated (rotary_percent 0.75): identical to the H3-Image rope.
- Final layer: norm + adaln_proj (10752 = 2 x 5376, 1 modality, bf16 in the file) -> video_out (5376 -> 96) / audio_out (5376 -> 32).
- Not read yet: packed_sequence.py / packed_tokens.py (sequence layout and the modality tags), pipeline_minimax_h3.py (4346 lines: sampler with flow shifts video 12.0 / audio 3.0, reference handling), vae.py (1501 lines), audio_vae, reference KV cache.

## M2 video VAE on the phone (done for T=2, 256x256)
- Source: Comfy-Org/MiniMax-H3 vae/minimax_h3_video_vae_int8_convrot.safetensors (2.8 GB; local copy backups/h3-ref2va/vae_dl/vae/). ## M4 windowed DiT (no token limit), like LTX
- blk.c MODE 50: M_A4 bit0 = only project this window's K/V into the global K/V buffers (slab offset M_A9), bit1 = K/V already there (queries of the window attend to M_A2 key tokens, chunked attention); M_NIMG = image slabs inside the window; M_FIRST == 2 = cache sync only (no HMX power request), M_REL 2 = flush x only.
- r2vrun: R2V_WIN=N slabs of 32 rows (default 32; automatic when ni+nt > 4000, R2V_WIN=0 forces the plain path): X / rope tables of all rows in host memory (Xh/Ch/Sh), per block pass 0 = K/V of every window, pass 1 = block per window; text encoder / refiner still use the plain blob. blob_meta.h of h3/hexagon/mega replaced by the flux3 one (M_A0..M_A11).
- Verified: windows vs plain 512x512 forward v rel 4.8 %, same fox picture.
- Measured (phone, forward = TE 14 s + step): 512x512 T=7 1792 rows step 48 s; 1024x1024 T=7 7168 rows 163 s; 1024x576 T=17 (56 frames) 9792 rows 260 s. Plain path limit was ~4400 rows (FastRPC mapping).
- Pitfall: 1000s of calls with M_FIRST=1 / M_REL=1 each (power request + resource release every call) ended in 8 consecutive HMX self-test failures (rc -77); fixed with FIRST once, then 2, REL 2 except the very last call.
