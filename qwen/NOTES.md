## Read the reference code (2026-11-08): exact model (ref/src/transformer_qwenimage21.py, pipeline_qwenimage21.py)
Sequence = [text tokens (interleaved with condition-image tokens for editing)] + [target image tokens]. Attention is BLOCK-CAUSAL: (q>=k) or same image block; text strictly causal, every image block (each condition image, the target) bidirectional. Target tokens see the whole prefix + themselves.
`causal_condition`: text and condition-image tokens are modulated from t=0, so their activations are step independent -> prefix K/V (post-RoPE) cached once per layer; denoise steps only run the TARGET tokens (queries) against [cached prefix K/V + own K/V]. => prefill (prefix only, t=0 row) once + 8 steps over target tokens only. Per step cost ~ 7.1B x 2 x N_target.
Block (no biases anywhere): h = h + tanh(gate1) * Attn( LN(h) * (1+scale1) ) ; h = h + tanh(gate2) * SwiGLU( LN(h) * (1+scale2) ); LN has no affine (eps 1e-6). SwiGLU = out( silu(gate_layer(x)) * proj(x) ) (GGUF has fused gate_up 4096->24576, check the order). Attention: to_q/k/v 4096->4096, per-head RMSNorm(128) on q,k, RoPE, to_out.
SHARED modulation: modulation = Linear(silu(temb), 4096->16384) = [scale1, gate1, scale2, gate2], the same 4 vectors for ALL 32 blocks (row for target tokens = real t, row for prefix tokens = t=0). temb = TimestepEmbedding(sin/cos 256 of 1000*t -> 4096 -> silu -> 4096) (cos first, sin second).
Final: norm_out: scale = Linear(silu(temb)) (scale only, no shift), LN(h)*(1+scale), proj_out 4096->64. txt_in: ZeroCenterRMSNorm(4096, eps 1e-6, weight stored as scale-1) -> Linear -> GELU(tanh) -> Linear. img_in: Linear 64->4096.
RoPE: theta 10000, axes dims (16,56,56) = frame,height,width, COMPLEX (adjacent pairs 2i,2i+1) form. Text tokens: all 3 axes = running position. Image block: frame = position reached so far, h and w centred on 0 (range -(h-h//2) .. h//2-1 per axis), position += max(h,w) after the block. (Adjacent-pair RoPE can be turned into the half-split form our kernels use by permuting the rows of to_q/to_k and the q/k norm weights per head: exact.)
Scheduler: flow-match Euler, sigmas = the 8 shipped values + terminal 0, shift 1.0 (no dynamic shift), timestep input to the DiT = sigma (it multiplies by 1000 inside), x += (s_next - s) * v.
Latents: randn (64, H/16, W/16) packed as tokens (h*w, 64), patch 1. Decode: latents*std+mean (vae/config.json) -> VAE decoder.
Text encoder: Qwen3-VL-8B, template "<|im_start|>system\nComprehend and analyze the provided prompt.<|im_end|>\n<|im_start|>user\n{prompt}<|im_end|>\n<|im_start|>assistant\n"; hidden_states[-1] is the output of the LAST decoder layer BEFORE the final norm (transformers 5 returns it normalised, they hook that away); the first drop_idx tokens (the system message) are dropped; empty prompt -> " ".
EDITING (TI2I): template "...<|im_start|>user\n<image1><|vision_start|><|image_pad|><|vision_end|>{prompt}<|im_end|>..."; condition images are resized to ~1 MP (calculate_dimensions(1024^2, ratio), multiples of 32), go through the Qwen3-VL VISION TOWER (needs mmproj, 1.16 GB, incl. DeepStack) AND the VAE encoder (argmax, normalised with latents_mean/std); each VLM image slot (<|image_pad|>) = 2x2 latent tokens; the condition latents replace those slots in the text stream; they are part of the cached prefix. The pipeline also composites RGBA over white for the vision tower only.
VAE: 2D-conv "image specialisation" of a Wan style 3D VAE (QwenImage21CausalConv3d is nn.Conv2d), RMS norm (F.normalize), attention block, Avg/DupUp shortcuts, spatial /16, z_dim 64 -> ONNX export + QNN HTP contexts per size like FLUX.2.

## Port plan
1. torch CPU reference (block-wise from the GGUF, dequantised) for DiT with prefix cache + TE + sampler; check against diffusers on tiny sizes / fp32.
2. DiT kernels from the MOSS ones: LN(no affine)+(1+scale), tanh gates, SwiGLU epilogue, Q != K sequence attention (queries = target tokens, keys = cached prefix + own), prefix prefill with block-causal mask (text causal, image blocks bidirectional), K/V cache buffers in DDR.
3. Pack: q8 tiles from Q5_K_S = ~7.9 GB per step read (8 steps = 63 GB): too slow; use a native 5-bit (q5a) record like q4a (~4.9 GB) and/or keep it RAM-resident for the 8 steps.
4. TE: Qwen3 layers (full attention, GQA 32/8, hd 128, q/k norm, plain RoPE for text-only) from the Qwen3.5 full-attention kernels; output = layer-35 residual before final norm.
5. VAE decoder (and later encoder) as QNN contexts; editing = + vision tower (mmproj), VAE encoder, prefix with image blocks.

## Kernel port design (read of hexagon/mega, session 3) — NO per-row modulation needed
- Two pass types, each with ONE modulation set: (A) prefill: rows = text (+ condition-image rows for edit), modulation from t=0 (mod0), causal mask (condition blocks bidirectional), writes post-norm/post-rope K,V into a per-layer cache (T=256 padded: 4 MB/layer, 134 MB total; edit adds ~0.5 MB/token/layer-sum... see 524 KB/token). - Host precomputes per pass vectors: [sc1, tanh(g1), sc2, tanh(g2)] (4 x 4096) -> existing k_ln_prep/k_lnmod_s (LN with mean, shift=0) and fp32 gate epilogue; no tanh on the DSP.

## TILE-EDGE DOTS FIX (2026-11-08)
User report: small pink/yellow/green/blue/purple dots in 768x1024 edit results. Found: all blobs sit at x=507 / x=267 = 5 px inside tile 0's right edge / 11 px inside tile 1's left edge of the 512-px decoder tiles (T=32, overlap 4 latents = 64 px). The HTP fp16 decoder produces wild values in the outermost ~12 px of a tile for some content (tile test: |out| up to 5.5 at a tile corner vs CPU 1.1) and the old feather ramp ((i+1)/(r+1)) gave those pixels 8-18 % weight.
Fix (vaetile.cpp, vaeenc.cpp): weight 0 for the outer M=min(24, overlap px/2) px of a tile edge that has a neighbour tile, ramp after it; tile output clamped to [-1,1] before blending; encoder: first/last latent of a tile gets weight 0. Error vs CPU decode near the old seams: 6.8/3.6 -> 2.1/1.5 (8-bit units), interior unchanged ~1.6. Encoder NPU latent differs 12 % rms from CPU but decodes to the same picture (round trip 2.3 vs 2.0 mean abs err), so not the cause. MOSS vaetile (FLUX decoder) has the same blend code and was not changed.

## MULTI-IMAGE EDITING (up to 3 condition images)
- Reference pipeline: `<image1>…<|vision_end|> <image2>…` template (one image slot run per picture), each picture resized to its own area/aspect, img_shapes = [cond1, cond2, cond3, target]; RoPE: text advances (p,p,p); every image block freezes the frame axis at p, h/w centred, p += max(h,w) after it; the target comes last; each condition block is bidirectional, the rest causal, all modulated from t=0 (prefix K/V cached).
- qwenrun: `QWEN_EDIT=dir` holds picture 0, `dir/1` and `dir/2` the others (each meta.txt/rgba.f32/px.f32/cond_raw.f32); ViT per picture (own grid), mrope in the encoder walks the sequence (cur += max(gh,gw) after every grid), DeepStack added at every image slot; prefix rows are text with each slot run replaced by that picture's img_in(latent) rows; tx/prefix cache keys hash all px files.
- DSP (qwen/hexagon/mega): `M_B2A/M_B2B/M_B3A/M_B3B` = further bidirectional blocks next to `M_BA/M_BB`; `blk.c` computes a per-row visibility limit lim(i) = max(i+1, end of i's block) and builds the partial-tile masks from it (de-duplicated, 16 distinct masks per slab at most), `k_softmax2pm` takes a mask index per tile. This also fixes the old single-block mask for a block start that is not tile aligned (tile count > 8 returned -1 and the diagonal tile stayed unmasked).
- App: `Qwen.prepareEdit(List<Bitmap>)`, per-picture condition size (k = 1: 0.4 Mpx; 2: 0.3; 3: 0.2, and target + conditions + 400 text tokens <= 6800 keys), files `edit_src.png`, `edit_src1.png`, `edit_src2.png`, UI: "+ Another picture" under the photo.
